# 云台 MPC 响应测试

`gimbal_mpc_response_test` 构造 yaw/pitch 参考轨迹，经过 TinyMPC 后可发送给真实云台，
直接在 GUI 中观察响应。没有相机、识别、弹道或 PlotJuggler 依赖。
这里按用户要求构造的是参考指令；反馈曲线始终来自云台板，不使用虚拟云台或模拟反馈。

## 启动

关闭占用云台串口的其他程序，在项目根目录编译：

```bash
cmake --preset default
cmake --build --preset default --target gimbal_mpc_response_test
```

只显示参考、规划及真实反馈，不发送任何控制或停控帧：

```bash
./build/gimbal_mpc_response_test configs/sentry.yaml
```

开启真实跟随：

```bash
./build/gimbal_mpc_response_test configs/sentry.yaml --enable-control
```

板端回传 `mode=1 / AUTO_AIM` 时才请求跟随。开火位在所有发送路径上都固定为 false。
初次收到有效反馈、链路恢复、进入自瞄模式或按 C 时，将实际姿态设为矩形中心。
默认完整宽度 6°、高度 3°，每秒一圈，MPC 与发送循环目标频率 200 Hz。
参考会在默认 1 秒内从当前实测位置平滑展开。

小范围、较快的参考例子：

```bash
./build/gimbal_mpc_response_test configs/sentry.yaml \
  --enable-control --width=4 --height=2 --frequency=3 --rate=200
```

`frequency` 是一秒内走完整矩形的圈数，`rate` 是主机规划/发送循环的目标频率。
实际反馈频率由板端决定，主机以更高频率发送不会提高板端测量采样率；两者分开显示。

## 界面与操作

鼠标拖动右侧滑条，按 Enter 或点击 Apply 应用：

| 参数 | 含义 |
|---|---|
| Yaw width / Pitch height | 完整宽高，单位度，分别允许 0..30° / 0..20° |
| Cycles / second | 每秒完整圈数，0.1..10 Hz |
| Corner radius | 圆角半径占短边一半的百分比，1..100%；数值越小越接近尖角矩形 |
| Transition ramp | 起步或参数切换时的平滑过渡时间，0.1..5 秒 |
| MPC max velocity | 两轴规划速度上限，1..720 度/秒 |
| Visible history | 波形显示最近 1..30 秒，立即生效，无须 Apply |

宽或高设为 0 时，剩余轴采用单轴正弦往复，方便分别调 yaw 或 pitch；两者均为 0 时保持中心。
矩形直边按恒定角度路径速度运行，圆角保持速度连续，MPC 按配置约束加减速。
修改频率和尺寸后会重新从实际位置过渡，不将旧周期相位直接套到新路径。

| 快捷键 | 操作 |
|---|---|
| Enter | 应用滑条参数，重新开始平滑过渡 |
| Space | 暂停/恢复；暂停释放控制，恢复从实际位置过渡 |
| C | 将当前实际姿态重设为中心，重启轨迹 |
| R | 清除波形历史与窗口误差统计，轨迹继续 |
| D | 切换待应用的绕行方向，再按 Enter 应用 |
| S | 导出内存中最近最多 30 秒 CSV |
| P | 保存当前波形面板 PNG |
| Q / Esc / Ctrl+C | 退出；控制模式先请求停控 |

鼠标移到波形区域可读取对应时刻的三条曲线数值。GUI 的参数、绘图、导出与控制循环
分线程运行。支持窗口状态查询的后端可用关闭按钮退出；不支持查询时使用快捷键退出。

## 波形与数据

左侧两列分别是 yaw、pitch，每列显示四组波形：

1. 角度：黄色参考、紫色 MPC 指令、青色真实反馈，单位度，相对当前中心显示。
2. 角速度：三者的速度，单位度/秒，实测值直接使用板端回传角速度。
3. 误差：黄色 REF−RX、紫色 CMD−RX、青色 REF−CMD，单位度。
4. 角加速度：参考、实际输出的 MPC 加速度、反馈角速度差分所得加速度。
   上行协议没有加速度字段；青色加速度是按真实接收时间差分，并使用 30 ms 时间常数
   低通后的估计，图中明确标为 `d(v)/dt + LPF`。

右侧显示二维路径、绝对角度、参考跟踪 RMSE、峰值误差、平均偏差，以及指令到实测的
RMSE。统计使用当前显示时间窗内有效的反馈/规划样本，暂停、丢反馈等缺失值不填 0。
模式、反馈年龄、串口连接代次、原始四元数/欧拉角同屏显示。

顶部显示实际循环频率、反馈频率、发送请求频率、MPC 求解时间、循环抖动与超期次数。
发送频率是主机请求发送的频率，包含停控帧，不是 MCU 执行确认。
每轴同时显示 MPC 迭代次数、收敛状态、约束触发及原始/对偶残差。

CSV / PNG 保存到 `out/gimbal_mpc_response/`，可用 `--output-folder` 修改。
CSV 记录时间、参考/规划/实测角度及其导数、误差、原始四元数、模式、控制状态、
反馈年龄、循环与求解耗时、频率、约束和收敛信息。角度类数据转换为度，缺失数据为 NaN。
每次重设中心、应用新参数或重新建立反馈后清除历史，避免把不同坐标原点和参数混在一份统计中。

## MPC 与通讯

复用仓库的 TinyMPC 和现有规划模型 `A=[[1,dt],[0,1]]`、`B=[[0],[dt]]`。
每轴状态是角度/角速度，输入是角加速度。与现有 `auto_aim::Planner` 一样，
以参考轨迹初始化状态，在包含过去/未来的 100 列窗口内优化，输出中间列；
它是给下位机跟踪的参考规划器，物理响应闭环仍由电控完成。
板端实测数据用于对比、误差统计和控制有效性判断，不被当成模拟对象的状态。

`dt=1/rate`，所以 200 Hz 时规划时间窗约为前后各 0.25 秒；100 Hz 时约为前后各 0.5 秒。
修改 rate 同时会改变离散步长和预瞄时长，进行不同参数对比时应保持 rate 一致。
CLI `--iterations` 控制每轴迭代上限，默认 10。耗尽迭代预算时仍可显示/发送有限的近似结果，
`converged=N` 明确表示未达到求解器容差；实际输出字段会限制在设置的角度范围、速度和加速度上限内。

直接读取传入 YAML 的 `com_port`、`Q_yaw`、`R_yaw`、`Q_pitch`、`R_pitch`、
`max_yaw_acc`、`max_pitch_acc`；加速度配置单位继续使用 rad/s²。
不应用自瞄的 yaw/pitch 补偿，不修改这些参数，也不通过此工具写入电控 PID 参数。

反馈超过 100 ms、模式不符、GUI 心跳超过 1 秒、参数切换期间旧结果失效或规划数值无效时，
控制模式改发停控帧。串口重连会重新从实际姿态建立中心；正常退出与循环异常都会请求停控。
始终保持开火位关闭。
